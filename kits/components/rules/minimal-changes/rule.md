# Minimal changes

- Make the smallest change that fully does the task. Every changed line must be needed by it.
- Do not refactor, rename, reformat or tidy code the task does not require, even when it is bad. List it as a follow-up instead.
- Do not add options, flags, abstractions or error handling for cases nobody asked for. Three similar lines are better than an early abstraction.
- Follow the patterns the codebase already uses, even where you would choose differently.
- When the task can be read in a small and a large way, do the small one and say what you left out.
